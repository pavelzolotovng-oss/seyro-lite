# Журнал изменений SEYRO Lite

## 2026-10-17 — Сброс транспорта при смене режима

- При переключении «Автоматический выбор» / «Ручной выбор» сбрасываются временный профиль и сохранённый ручной транспорт; если VPN подключён, выполняется переподключение для применения режима.
- Служба получает флаг `by_auto` для каждой новой сессии и сохраняет успешный транспорт только для соединений, запущенных в автоматическом режиме.
- Лог возможностей сети переведён на уровень V; для внеочередного probe вместо `unknown` используется `n/a`.


## 2026-10-17 — Автовыбор по успешному probe

- Транспорт больше не сохраняется при состоянии connected: это подтверждает запуск Xray/TUN, но не прохождение трафика.
- Последний успешный транспорт записывается один раз за VPN-сессию после первого успешного probe; флаг сбрасывается при остановке и новом подключении.
- Очередь автовыбора: последний успешный транспорт, затем XHTTP → TCP → gRPC и остальные доступные транспорты. В журнал выводятся очередь и номер попытки.


## 2026-10-17 — Автовыбор профиля

- В автоматическом режиме приложение сначала использует транспорт, который последним дошёл до состояния `connected`, если он присутствует в текущей подписке.
- Если запуск выбранного профиля завершается ошибкой на старте Xray, приложение последовательно пробует следующие профили из подписки и пишет ход переключения в журнал отладки.
- Ручной выбор сохраняет выбранный транспорт; переключение в автоматический режим сбрасывает временный выбор, чтобы следующий запуск действительно выполнил автовыбор.
- Ограничение первой версии: резервное переключение срабатывает при ошибке запуска Xray. Оно пока не измеряет задержку всех профилей и не подтверждает доступность внешнего интернета перед сохранением последнего успешного транспорта.


## 2026-10-16 — Автообновления

- **Проверка обновлений:** приложение при запуске проверяет GitHub Releases не чаще одного раза в 6 часов, сравнивает `versionCode`, показывает диалог новой сборки и позволяет скачать APK и открыть системный установщик Android. Доступна принудительная проверка.
- **Публикация:** каждая успешная сборка GitHub Actions автоматически публикуется как prerelease `debug-build-<номер>` с APK `app-debug.apk`.
- **Версии:** `versionName` формируется как `0.9.<номер сборки>`, а `versionCode` берётся из номера запуска GitHub Actions.
- **Подпись:** сохранена конфигурация постоянного keystore, чтобы APK можно было устанавливать поверх предыдущей версии. Установка подтверждается системным диалогом Android.
- **Безопасная установка:** добавлены AndroidX FileProvider, файл разрешённых cache-путей и разрешение на запрос установки APK.

Все заметные изменения проекта фиксируются здесь. История отдельных правок также доступна в [GitHub Commits](https://github.com/pavelzolotovng-oss/seyro-lite/commits/feature/profile-subscription-link).

## 2026-10-16

- **Версия приложения:** повышена с `0.8` до `0.9`, чтобы различать APK после очередных изменений. `versionCode` продолжает автоматически формироваться из номера сборки GitHub Actions.
- **Коммит версии:** `6db1ba4d90a95891cbe350c92900bc73e16404fc` — Bump app version to 0.9.

- **Фильтрация сетевых callback по VALIDATED:** `onCapabilitiesChanged()` проверяет `NET_CAPABILITY_VALIDATED`; повторные callback с тем же состоянием той же сети больше не запускают внеочередной probe. Проверка запускается при первом снимке/смене сети или изменении состояния в сторону validated; 3-секундный дебаунс сохранён как дополнительная защита.
- **Сброс состояния:** сохранённый снимок возможностей очищается при снятии callback.
- **Коммит кода:** `259117aa8f18eb1a24f9366824cb0b3dc77c95aa` — Filter repeated network capability callbacks using VALIDATED.

- **Дебаунс сетевых probe:** события `onAvailable()` и `onCapabilitiesChanged()` проходят через `triggerProbeFromNetwork()`; повторные события в пределах 3 секунд пропускаются с диагностикой уровня V. При снятии сетевого callback таймер дебаунса сбрасывается.
- **Коммит:** `e21b41177b624051a0c0b794e618c50ab27a3b10` — Debounce network-triggered probes.

- **Уровень V в DebugLog:** добавлен `DebugLog.v(...)`; как и `d(...)`, он пишет в Logcat и постоянный журнал только в Debug-сборке, в Release полностью отключён.
- **Шумные probe-сообщения:** «Probe пропущен: Xray ещё не запущен» понижен с D до V.
- **Версия приложения:** `versionName` изменён на `0.8`; `versionCode` по-прежнему задаётся номером сборки.
- **Коммиты:** `621484d0341cc2a143428de892956b3091ce9cff` (DebugLog V), `1855d90ebe85c12292df696b3405538600dc32e0` (уровень probe), `a672d435a1ee295469a5dcfde5006c73d647d56c` (версия 0.8).

- **NetworkCallback:** добавлено разрешение `ACCESS_NETWORK_STATE` в AndroidManifest.xml для корректной регистрации `registerDefaultNetworkCallback()` и устранения `SecurityException`.
- **Коммит манифеста:** `1422dc43d95cf6f9c643ea5ca83771efdcca5518` — Add ACCESS_NETWORK_STATE permission for network callback.

- **HEV_STATS:** отключено журналирование интервалов с низким трафиком: менее 50 TX/RX пакетов и менее 4096 TX/RX байт за интервал.
- **Интервал статистики:** вместо фиксированного «за 30с» используется фактическая длительность по `SystemClock.elapsedRealtime()`.
- **Базовые счётчики:** обновляются и в idle-интервалах, чтобы следующая дельта не включала подавленный период.
- **Перезапуск VPN:** таймер интервала статистики обнуляется при запуске сбора.
- **Коммит кода:** `bbfd7f887fda90b92595aa9611b9fd2ca7733942` — Suppress idle HEV stats logs and measure real intervals.


- **Исправление NPE при обновлении подписки:** уведомление Toast теперь показывается через `runOnUiThread`, а не из фонового потока.
- **Диагностика:** при ошибке обновления метаданных записываются тип, сообщение и полный стек исключения.
- **Журнал подключения:** удалена дублирующая запись нажатия кнопки подключения; оставлен один вызов `DebugLog.i`.
- **Коммит:** `5e768ed1943df465f9f4bbbf8acb03498a961805` — Fix subscription refresh toast thread and diagnostics.


- **Критический баг адаптивности probe исправлен:** при возврате в UI лестница интервалов больше не сбрасывается автоматически. `reset=false` при `sinceLast <= 2 × interval`; `reset=true` и сброс к 30 секундам — только если прошло больше двух текущих интервалов.
- **Журналирование:** в сообщении «Внеочередной probe» сохраняются `sinceLast`, `interval` и фактический `reset`.
- **Коммит:** `40232b14a5714367960b56a5955fe0ec42112e19` — Fix adaptive probe reset threshold.

- **Probe / диагностика:** уточнены сообщения `PROBE` в `SeyroVpnService`: начало проверки, успешный результат с `delay`, `elapsed`, `streak/3` и `step`, а также ошибка со сбросом адаптивного интервала до 30 секунд.
- **Журналирование:** события probe отправляются и в Logcat (`Log.d("PROBE", ...)`), и в постоянный журнал отладки приложения.
- **Адаптивный интервал:** сохранена последовательность 30 → 60 → 120 → 180 → 240 → 300 секунд; увеличение шага после трёх успешных проверок, сброс при ошибке и при внеочередном запуске.
- **Коммиты кода:** `e6456665a3231ef86ad299d712372fbb10752f54` — Clarify adaptive probe diagnostics; `7fef1b9efea464c13b59f5d5af365229d1dc0493` — Avoid duplicate probe log entries (оставлена единая точка логирования, чтобы не дублировать строки).

## 2026-10-15

- Снижена частота статистики трафика; журналируются изменения счётчиков, а не повторяющиеся абсолютные значения.
- Добавлены адаптивные проверки доступности и внеочередной probe при изменении сети и возвращении в приложение.
- Добавлено подробное журналирование этапов подключения и обновление журнала отладки в интерфейсе.
